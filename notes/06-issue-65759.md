## 1. 這個 issue 在要什麼？現在怎麼讀 HDF5？

- 要的是一個和 `read_parquet`、`read_numpy` 同類的 `ray.data.read_hdf5(paths)`，直接把 `.h5` 檔讀成 Dataset。
- 現況：沒有內建 reader。使用者要自己用 `h5py`，例如先 `read_binary_files` 拿到整個檔案的 bytes，再用 `h5py.File(io.BytesIO(...))` 解析（留言的 Option B）。
- 推論：這個做法要把整個檔案讀進記憶體，所以大檔案不好用，這是做原生 reader 的動機。

## 5. 相依套件：h5py 怎麼處理

- repo 的慣例是 `_check_import`，定義在 `python/ray/data/_internal/util.py:321`：`def _check_import(obj: Any, *, module: str, package: str) -> None:`，找不到模組時丟 `ImportError`，訊息是 `Install '{module}' by running `pip install {package}`.`（`:335-338`）。
- 用法都在 datasource 的 `__init__`：`lance_datasource.py:29`：`_check_import(self, module="lance", package="pylance")`，接著 `:31` 才 `import lance`；`image_datasource.py:47`：`_check_import(self, module="PIL", package="Pillow")`；`zarrv2_datasource.py:288`：`_check_import(self, module="zarr", package="zarr")`。
- 另一種是 `tfrecords_datasource.py:43`：在函式裡直接 `import tensorflow as tf`（純 lazy import，沒有友善訊息）。
- 推論：`HDF5Datasource.__init__` 應該 `_check_import(self, module="h5py", package="h5py")`，`_read_stream` 裡再 `import h5py`。
- 測試環境 requirements：Data 的測試相依在 `python/requirements/ml/data-test-requirements.txt`（zarr 在 `:30-31`，lerobot 在 `:57`）。推論：h5py 加在這個檔最合適。
- 但 h5py 其實**已經**在 Data 的 CI lock 裡：`python/deplocks/ci/data-base-ci_depset_py3.12.lock:1974`：`h5py==3.12.1`，來源註解是 `keras`、`tensorflow`（透過 tensorflow 間接裝入）。推論：測試也許不改 requirements 就能跑，但依賴間接來源較脆弱，要不要明確加是要問維護者的點。
- 重新產生 lock 檔：有規定。`.claude/skills/ray-dependencies/SKILL.md`（工作流規則 1）：「Do **not** hand-edit `python/requirements_compiled*.txt`」，只改 source requirement 檔；重新鎖定用 `bazelisk run //ci/raydepsets:raydepsets -- build --all-configs`（同檔「Recompile + relock everything」段），Data 相關設定是 `ci/raydepsets/configs/ci_data.depsets.yaml`。
- 注意：`h5py` 不要加進 `python/requirements.txt` 或 `python/setup.py`（那是 `pip install ray` 的必要相依，SKILL.md 規則 4）。這是 optional 相依。

## 6. 安全規則

`.claude/rules/security.md` 第 4 條原文：

> A new or changed Ray Data datasource that yields a `pa.Table` deserialized from external input (parquet, Arrow IPC, a service or library returning Arrow) without calling `raise_on_pickle_object_columns(table)` before yielding or materializing it is a remote code execution bug and should be avoided.

- 函式定義：`python/ray/data/_internal/object_extensions/arrow.py:24`：`def raise_on_pickle_object_columns(table: "pa.Table") -> None:`；它檢查有沒有 `ray.data.arrow_pickled_object` 擴充型別，有就丟 `ValueError`；設環境變數 `RAY_DATA_AUTOLOAD_PICKLE_OBJECT_SCALAR=1` 可關閉（`:16-18`）。
- 其他 datasource 的呼叫方式：讀出 table 後、yield 前馬上呼叫。例如 `lance_datasource.py:220-223`：先 `table = pyarrow.Table.from_batches([batch])`，再註解「raise unless the user has explicitly opted in」，然後 `raise_on_pickle_object_columns(table)`，最後才 `yield table`。其他呼叫點：`parquet_datasource.py:1002`、`orc_datasource.py:32`、`lerobot_datasource.py:862`。
- repo 有自動檢查：`python/ray/data/tests/unit/datasource/test_pickle_gate_coverage.py:21` 起，用 regex 掃每個 datasource 模組，若含 `pq.read_table(`、`.to_table(`、`.read_all(` 等讀 Arrow 的呼叫，卻沒有字串 `raise_on_pickle_object_columns`，測試就失敗（`:46-50`、`:70-74`）。
- 推論：**規則的字面條件是「從外部輸入反序列化出 `pa.Table`」。** h5py 讀出的是 numpy 陣列，不是 Arrow，所以字面上多半不適用；而且 HDF5 檔本身不能內嵌 Ray 的 pickled Arrow 擴充型別。
- 推論：但 h5py 讀到 object dtype（vlen 字串、bytes、reference、含 vlen 的 compound）時，numpy 陣列是 `object` dtype。Ray 轉成 Arrow 失敗時，會退回 `ArrowPythonObjectArray`（`_internal/tensor_extensions/arrow.py:367`：`return ArrowPythonObjectArray.from_objects(column_values)`），這個是 Ray 自己在行程內 pickle 的，並非讀檔時反序列化外部資料。所以風險不是遠端程式碼執行，而是「資料悄悄變成 pickled object 欄位」。
- 建議（需維護者確認）：(1) 若最後經由 `pa.Table` 輸出，仍呼叫 `raise_on_pickle_object_columns(table)`，成本低、保守；(2) 或明確拒絕 object dtype。若不呼叫，要確認不會被 `test_pickle_gate_coverage.py` 誤判（程式裡不要出現那串 regex 的 Arrow 讀取呼叫，或加進 `_ALLOWLIST` 並寫理由）。另外 `numpy` 的 `allow_pickle` 慣例（`read_numpy` 預設 `allow_pickle=False`）可作參考。

## 7. 要先跟維護者確認的設計問題

1. **一個 row 對應什麼？** 留言提議「第一個軸的一個元素 = 一個 row」（例如 shape `(N,T,D)` 變成 N 個 row）；另一種是「一個 dataset（或一個檔案）= 一個 row」。這決定 schema 與 `_rows_per_file()`（基底預設回傳 `None`，`file_based_datasource.py:459-461`）。
2. **多個 dataset／group 怎麼處理？** 只讀指定的 key（例如 `datasets=[...]` 參數）？每個 dataset 變一個欄位（要求第一軸長度一致）？巢狀 group 要攤平還是用路徑 `a/b/c` 當欄位名？
3. **要不要依 chunk 切分讀取任務？** `FileBasedDatasource` 是「以檔案為單位」排任務，沒有單檔內切分（推論，依 `get_read_tasks` 的設計）。若要單檔內依 chunk 平行，要像 `ZarrV2Datasource(Datasource)`（`zarrv2_datasource.py:269`）那樣直接繼承 `Datasource`，複雜度大幅上升。第一版是否只做「一檔一任務」？
4. **欄位名稱怎麼定？** 用 HDF5 的 dataset 名稱？單一 dataset 時是否像 `read_numpy` 用固定名 `"data"`（`numpy_datasource.py:14`）？
5. **相依與安全：** 測試環境要不要明確加 h5py（現況只是間接來源）？object／vlen 字串要支援還是拒絕？是否要呼叫 `raise_on_pickle_object_columns`？
6. （補充）h5py 要求檔案物件支援 seek／read；`_read_stream` 拿到的是 `pyarrow.NativeFile`（`file_based_datasource.py:463`）。推論：多半可直接傳給 `h5py.File`，但我沒有實測（沒有 h5py）；`numpy_datasource.py:41-47` 的作法是先 `readall()` 進 `BytesIO`，是保底寫法。
